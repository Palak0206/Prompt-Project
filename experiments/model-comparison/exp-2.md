# Development Task 01: Technical Requirements Comparison

## Objective

Compare the technical requirements specifications independently generated by ChatGPT and Claude for the AI-Powered Timetable and Study Plan Generator.

## Models Compared
- ChatGPT
- Claude

## Comparison Summary

| Evaluation Area | ChatGPT | Claude |
|---|---|---|
| Functional requirements | Detailed | Detailed |
| Input design | Comprehensive | Comprehensive |
| JSON structure | Good | More refined |
| Prompt engineering | Good | Comprehensive |
| Constraint handling | Good | Strong |
| Validation architecture | Good | Strong |
| Backend architecture | Simpler | More modular |
| API failure handling | Good | More comprehensive |
| Testing strategy | Good | More systematic |

## Key Findings

### ChatGPT

Strengths:
- Simpler and easier-to-understand backend structure.
- Good input field recommendations.
- Detailed validation requirements.
- Recommends avoiding invented syllabus topics.
- Suitable for incremental implementation.

Limitations:
- Less detailed separation of planning and validation.
- Less developed feasibility analysis.
- Some architectural responsibilities could be separated further.

### Claude

Strengths:
- Clearly separates Python responsibilities from LLM responsibilities.
- Introduces feasibility checking before API calls.
- Separates hard constraints and soft constraints.
- Recommends prompt versioning.
- Provides detailed API failure handling and testing scenarios.

Limitations:
- Proposed architecture is more complex.
- Priority-budget calculations require additional design decisions.
- Proposed JSON structure does not include clock times despite recommending overlap validation.
- Suggests allowing generic topic generation when syllabus information is absent, which needs careful handling.

## Final Technical Decisions

The project will combine the strongest recommendations from both specifications.

1. Use Python and Flask with a modular monolithic architecture.
2. Use an LLM API for timetable generation.
3. Construct prompts dynamically from validated student information.
4. Use JSON as the structured output format.
5. Use Python for input validation, date calculations and independent timetable validation.
6. Use Pydantic for structured data validation.
7. Implement bounded regeneration when timetable validation fails.
8. Use HTML, CSS and JavaScript for the frontend.
9. Use Pytest for automated testing.
10. Maintain prompt versions and record evaluation results.

## Features Excluded from Initial MVP

- User authentication.
- Database persistence.
- PDF export.
- Rule-based fallback generator.
- Multiple API providers.
- Advanced weighted subject-priority calculations.

These may be considered as future enhancements if required.

## Important Design Principles

- The LLM must not be trusted to perform arithmetic or enforce constraints.
- Python must independently verify generated timetables.
- Specific syllabus topics must not be invented when the student has not provided them.
- Study durations will be stored in integer minutes.
- Only validated timetables will be displayed.
- All API keys will remain on the backend.

## Conclusion

Claude provided stronger separation of responsibilities and more detailed validation architecture, while ChatGPT provided a simpler implementation structure and useful input-design recommendations.

The final project architecture combines both approaches while excluding unnecessary complexity.
